# 4. Compliance Matrix

## 4.1 Purpose

The compliance matrix provides a structured method for demonstrating how the proposed Maritime Mission Support System (MMSS) addresses the requirements identified by NorthStar Maritime Services.

Each requirement is mapped to the corresponding proposal section and supporting evidence. This approach supports proposal review, requirements traceability, and verification.

## 4.4 Compliance Status Definitions

The following status definitions will be used during proposal review:

| Status | Definition |
|---|---|
| **Compliant** | The proposed solution addresses the stated requirement. |
| **Partially Compliant** | The proposed solution addresses the requirement with identified limitations or conditions. |
| **Non-Compliant** | The proposed solution does not currently satisfy the requirement. |
| **To Be Confirmed** | Additional customer, technical, or SME information is required before compliance can be confirmed. |

## 4.5 Compliance Review Process

The compliance matrix will be reviewed throughout proposal development to ensure that:

- Each customer requirement has a documented response.
- Proposal references remain accurate.
- Compliance claims are supported by technical content.
- Requirements are not unintentionally omitted.
- Changes to requirements are reflected in the proposal.
- Supporting evidence can be identified for each compliance claim.

Any requirement that cannot be confirmed should be escalated for review rather than being incorrectly identified as compliant.

## 4.6 Traceability

The compliance matrix will serve as a central reference between customer requirements and supporting proposal content.

Each requirement will be traceable to:

**Customer Requirement → Proposal Response → Technical Solution → Deliverable → Verification**

A detailed Requirements Traceability Matrix will be maintained separately to provide additional implementation-level traceability.
